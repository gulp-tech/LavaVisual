# LavaVisual — Fabric Multi-Version

Лавовые ESP-рамки, трассеры и просвечивающие модели для клиента Minecraft.
Одинаковые клавиши, формат настроек и цветовая палитра во всех адаптерах.

## Скачать и установить

Основной файл: **[`artifacts/lavavisual-1.1.0-multiversion.jar`](artifacts/lavavisual-1.1.0-multiversion.jar)**.
На странице файла GitHub нажмите **Download raw file**.

1. Установите Fabric Loader **0.19.5 или новее** для своей версии Minecraft.
2. Установите **Fabric API именно для этой версии Minecraft** — см. таблицу.
3. Удалите предыдущий JAR LavaVisual из `.minecraft/mods/`.
4. Поместите туда **один** `lavavisual-1.1.0-multiversion.jar`.

Не устанавливайте bundle вместе с отдельным адаптером или старой версией мода.
На сервер мод ставить не нужно. Fabric API и сама игра в JAR не включены.

### Точные версии, включённые в bundle

| Minecraft Java | Java | Fabric API | Отдельный JAR (альтернатива bundle) |
|---|---|---|---|
| **1.20.4** | 17+ | 0.97.2+1.20.4 | `lavavisual-1.0.0+mc1.20.4.jar` |
| **1.21.4** | 21+ | 0.119.4+1.21.4 | `lavavisual-1.1.0-mc1.21.4.jar` |
| **26.2** | 25+ | 0.161.0+26.2 | `lavavisual-1.1.0-mc26.2.jar` |

**Это не сплошная поддержка диапазона 1.21.4–26.X.** Версии 1.21.5–1.21.11,
26.1.x, 26.3 и последующие в эту сборку не включены. Для них нужны отдельные
адаптеры и проверки. Непроверенные версии намеренно отклоняются, вместо того
чтобы запускать на них несовместимые миксины. Поддержка будущих 26.X не обещается.

### Как работает один JAR

Внешний мод `lavavisual_bundle` не содержит Java-кода и требует `lavavisual`.
Внутри находятся три вложенных Fabric-модуля с одним ID `lavavisual`, но
разными точными зависимостями от Minecraft/Java. Решатель зависимостей Fabric
выбирает **один подходящий адаптер**; классы и миксины остальных не загружаются.
Это настоящая упаковка jar-in-jar, а не изменение номера версии в манифесте.

## Управление

| Клавиша | Действие |
|---|---|
| **V** | Включить/выключить весь мод |
| **B** | ESP: 3D → 2D → выключен |
| **J** | Трассеры |
| **K** | Chams моделей |

Переназначение: **Настройки → Управление → LavaVisual**.
Визуалы включены по умолчанию. Изменения настроек сохраняются сразу.

## Визуалы

- **3D ESP:** рёбра bounding box с вертикальным градиентом
  `#8B0000 → #FF0000 → #FF6B00`; средняя точка каждого вертикального ребра красная.
- **2D ESP:** плоская вертикальная рамка-billboard, поворачивающаяся к камере
  по yaw. Это геометрия в мире, не экранный прямоугольник HUD.
- **Tracers:** линии от точки перед камерой к интерполированному центру цели;
  прозрачность и цвет зависят от дистанции.
- **Chams:** отдельный полупрозрачный лавовый проход основной анимированной
  модели без проверки глубины и без записи в depth buffer. Это не залитые боксы.
- Фильтры игроков и мобов; ограничение дистанции и числа целей.

## Настройки

Общий для всех версий файл: `.minecraft/config/lavavisual.json`.
Для ручного редактирования закройте игру; файл читается при её запуске.

```json
{
  "enabled": true,
  "boxMode": "BOX_3D",
  "tracers": true,
  "chams": true,
  "players": true,
  "mobs": true,
  "maxDistance": 96.0,
  "maxEntities": 128,
  "chamsAlpha": 0.38
}
```

`boxMode`: `OFF`, `BOX_3D`, `BOX_2D`. Дистанция: 8–256 блоков, лимит:
1–512 целей, прозрачность Chams: 0.05–0.85. Собственный игрок, камера,
мёртвые, невидимые сущности и наблюдатели исключены. Дружественные мобы
включены. При достижении лимита выбираются первые подходящие сущности
в порядке обхода мира, не обязательно ближайшие.

## Сборка из исходников

Нужен доступ к Fabric Maven, Maven Central, серверам Minecraft и Gradle.
Каждый адаптер имеет независимые версии Java/Loom/Gradle:

```bash
# Minecraft 1.20.4 — JDK 17
./gradlew build

# Minecraft 1.21.4 — JDK 21
cd ports/mc1.21.4
./gradlew build

# Minecraft 26.2 — JDK 25
cd ../mc26.2
./gradlew build
```

На Windows используйте `gradlew.bat`. Готовые файлы — в `build/libs/`
соответствующего проекта. `*-sources.jar` не предназначен для установки.

Для повторной упаковки bundle скопируйте основные JAR трёх адаптеров в
`artifacts/` и из корня выполните:

```bash
python3 tools/package_bundle.py
# Проверка выбора адаптера настоящим решателем Fabric (Gradle 9.5.1, Java 25):
gradle -p tools/bundle-test test
```

CI `.github/workflows/ports.yml` собирает оба новых адаптера, запускает
тесты, упаковывает bundle и публикует его в `artifacts/` рабочей ветки.
`SHA256SUMS`, `BUILD.txt` и `ADAPTERS.txt` указывают контрольные суммы
и происхождение сборок. Бинарные коммиты помечены `[skip ci]`.

## Архитектура и проверки

- **1.20.4:** MatrixStack, VertexConsumerProvider, WorldRenderEvents,
  дополнительный проход EntityModel через Mixin.
- **1.21.4:** отдельный адаптер для LivingEntityRenderState, BufferAllocator,
  нового формата цвета Model.render и изменённых состояний RenderLayer.
- **26.2:** LevelExtractionEvents → неизменяемый снимок кадра →
  LevelRenderEvents/SubmitNodeCollector. Собственные RenderPipeline и
  RenderType; Chams использует отложенную отправку анимированной модели.
  На этапе рисования ESP не читает живые сущности или ClientLevel.
- JUnit проверяет палитру каждого адаптера.
- `tools/bundle-test` использует настоящий Fabric ModResolver: выбор ровно
  одного адаптера для каждой целевой версии и отказ для неподдерживаемых
  версий/неподходящей Java.
- `Client startup smoke` запускает клиенты 1.21.4 и 26.2 под Xvfb и проверяет
  инициализацию мода, миксинов и ресурсов. Эта проверка **не заходит в мир**
  и не подтверждает правильность отображения ESP/Chams в игре.

## Ограничения

Игровая сцена, просвечивание за стеной, внешний вид на разных GPU и FPS
требуют отдельной проверки. Полное пиксельное совпадение между версиями
не гарантируется: их игровые шейдеры и пайплайны различаются.

Chams наследует frustum/distance culling оригинального рендера: мод не
возвращает модели, которые игра вообще не отправляет на рендеринг.
Броня, предметы в руках и feature-renderer слои отдельно не перекрашиваются.
Sodium, Iris, шейдерпаки, Fabulous и другие моды, меняющие LivingEntityRenderer,
не проверены. Redirect может конфликтовать с аналогичными миксинами.

Перед использованием проверьте в чистом Fabric-клиенте игрока и мобов за
стеной, движение, третье лицо, переключатели, перезапуск, смену измерения и
обычный рендер после отключения визуалов. Используйте мод в своём мире или
на серверах, где такие визуалы разрешены.
